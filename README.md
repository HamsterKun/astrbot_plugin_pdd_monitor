# 多多盯价

用关键词盯住拼多多搜索结果里的最低价，刷新历史最低价时主动推送到群；群内 @机器人 说「今日行情」查看全部监控项的现价与涨跌。

| 项目      | 值                                              |
| ------- | ---------------------------------------------- |
| 插件目录名   | `astrbot_plugin_pdd_monitor`                   |
| 数据目录    | `data/plugin_data/astrbot_plugin_pdd_monitor/` |
| 依赖      | `httpx`、`jieba`；可选 `curl_cffi`                 |
| AstrBot | ≥ 3.4.28                                       |

---

## 特性

| 功能    | 说明                    |
| ----- | --------------------- |
| 关键词监控 | 一条指令添加一个关键词，不需要商品链接   |
| 定时巡检  | 默认 30 分钟一轮，请求串行、间隔随机  |
| 离群剔除  | 先从整页商品里剔掉价格离群的配件、外设   |
| 标题匹配  | 分词比对标题，选出真正要对标的那一件    |
| 史低推送  | 刷新历史最低价时推送到已绑定的会话     |
| 今日行情  | 查询全部监控项的现价、较昨日涨跌、历史最低 |
| 每日播报  | 可选，在指定时间自动推送一次行情      |
| 风控退避  | 被限流时自动冷却，不硬顶          |
| 取价诊断  | 排查单个关键词取不到价的原因        |

---

## 安装

1. 把 `astrbot_plugin_pdd_monitor` 整个目录放进 AstrBot 的 `data/plugins/`。
2. 在 WebUI 插件管理页重载插件，或重启 AstrBot。
3. 打开插件配置，填入 `cookie`（见下一节）。
4. 在群内发送 `/盯价 add 纸巾` 验证。

## 配置 Cookie

`cookie` 是唯一的必填项，必须是一条**已登录**的拼多多 Cookie。缺了它，搜索页只会返回不含任何商品的空壳页面。

### 一、手机端获取

1. 手机浏览器打开 `https://mobile.yangkeduo.com/`，登录。
2. 随便搜一个词（如「纸巾」），确认能正常出商品列表。
3. 在地址栏把当前网址替换成下面这段并回车，页面会显示整条 Cookie：
   ```
   javascript:document.body.innerText=document.cookie
   ```
   部分浏览器会过滤 `javascript:` 前缀，可以先手动输入 `java` 再粘贴剩余部分。
4. 全选页面文字并复制。

### 二、电脑端获取

1. 浏览器打开 `https://mobile.yangkeduo.com/`，扫码登录。
2. 按 `F12` 打开开发者工具，切到 **Network（网络）** 面板。
3. 刷新页面，点列表里任意一条 `mobile.yangkeduo.com` 的请求。
4. 在 **Headers → Request Headers** 里找到 `Cookie:`，复制它后面的整条值。

### 三、粘贴

整段粘进 `cookie` 配置项即可，不需要手动清理。下面这些情况插件都会自动处理：

- 带 `Cookie:` 或 `cookie：` 前缀
- 从开发者工具整段复制，中间夹了 `Host:`、`User-Agent:` 等其他请求头
- 长 Cookie 被折成多行
- 首尾多了引号或分号

验证是否配对成功：执行 `/盯价 debug 纸巾`，输出末尾会有一行

```
cookie：218 字符、含 PDDAccessToken、含 pdd_user_id
```

显示 `缺 PDDAccessToken` 说明复制的不是登录态 Cookie（通常是只拿到了未登录时的匿名 Cookie），重新登录后再取一次。

### 四、账号要求

- **用日常在用的主号。** 风控按账号计算，新注册的小号、长期不登录的号，搜索页大概率直接返回「系统繁忙」。
- Cookie 等同于账号登录凭证，不要贴到聊天、截图或公开仓库。插件只把它放进请求头，不写入日志、数据文件或聊天回复。
- 换设备登录、退出登录、修改密码都会让旧 Cookie 失效，届时 `/盯价 debug` 开始报错，重新取一条即可。

## 配置项

| 键                         | 类型     | 默认           | 说明                                            |
| ------------------------- | ------ | ------------ | --------------------------------------------- |
| `cookie`                  | string | 空            | 拼多多网页 Cookie，必填，须含 `PDDAccessToken`           |
| `user_agent`              | string | 空            | 留空用内置 iPhone Safari UA；填取 Cookie 那台手机的 UA 最安全 |
| `transport`               | string | `auto`       | `auto` / `curl_cffi` / `httpx`，决定是否伪装 TLS 指纹  |
| `impersonate`             | string | `safari_ios` | curl_cffi 模拟的浏览器指纹                            |
| `warmup_home`             | bool   | true         | 首轮巡检前先访问一次首页，获取基础设备 Cookie                    |
| `search_sort`             | string | `price`      | 搜索页排序：`price` 升序 / `_price` 降序                |
| `keyword_filter_by_title` | bool   | true         | 按标题分词匹配选品；关闭则始终取最低价                           |
| `title_match_top_n`       | int    | 5            | 参与比对的前 N 条商品，1~20                             |
| `filter_price_outliers`   | bool   | true         | 匹配前先剔除价格离群的商品；关闭则全部参与匹配                        |
| `outlier_k`               | int    | 3            | 离群剔除严格程度，1~6，越小越狠                             |
| `check_interval_minutes`  | int    | 30           | 巡检间隔（分钟）                                      |
| `request_timeout`         | int    | 15           | 单次页面请求超时（秒）                                   |
| `notify_at_new_low`       | bool   | true         | 是否推送史低提醒                                      |
| `max_goods`               | int    | 50           | 最多监控的关键词数量                                    |
| `daily_report_time`       | string | 空            | 每日自动播报时间，如 `20:00`；留空关闭                       |
| `risk_backoff_max_hours`  | int    | 8            | 触发限流后的最长冷却时间（小时）                              |

**`search_sort`** 保持默认的 `price`。改成 `_price`（降序）后第一页是最贵的一批商品，在这批里取最小值会得到虚高的「最低价」。

**`title_match_top_n`** 只影响本地比对范围，不影响请求次数——所有候选商品都在同一次搜索响应里，取 5 条还是 20 条对风控没有区别。调大可能把价格高出很多的商品也纳入比对，调小可能把真正匹配的那条排除在外。

**`filter_price_outliers`** 与 **`outlier_k`** 管的是「匹配之前的初筛」，见「取价规则 · 价格离群剔除」。默认的 3 是标准值，只剔比中位数低一大截的那些：调到 1~2 更严格，可能连便宜的二手、拆机件一起剔掉；调到 5~6 更宽容，只剔差几十倍的极端项。`keyword_filter_by_title` 关掉时这一层仍然生效（它决定的是「取哪一档价格」，不是「怎么选品」）。

**`check_interval_minutes`** 建议不低于 20。监控项多时把间隔调大更稳。

## 指令

| 指令                | 说明                                   |
| ----------------- | ------------------------------------ |
| `/盯价 add <关键词>`   | 添加监控，可用竖线附加备注：`/盯价 add 9700X \| 备用机` |
| `/盯价 del <序号>`    | 删除监控，序号见 `/盯价 list`；也可直接填关键词         |
| `/盯价 list`        | 监控列表                                 |
| `/盯价 info <序号>`   | 单项详情：现价、史低、最低价商品、最近 7 次记录            |
| `/盯价 check`       | 立即执行一轮巡检                             |
| `/盯价 debug <关键词>` | 实时搜索一次，输出价格明细、匹配过程与 Cookie 状态        |
| `/盯价 on`          | 开启本群史低推送                             |
| `/盯价 off`         | 关闭本群史低推送                             |
| `/盯价 help`        | 指令列表                                 |

- `多多`、`拼多多`、`价格监控`、`比价` 均可代替 `盯价`。
- 添加监控时自动绑定当前会话，不需要再发 `/盯价 on`。
- 指令名使用中文，避免部分客户端把 `/pd` 之类的前缀转换成表情。

## 取价规则

### 一、盯的是关键词

插件不认商品链接，只认关键词。它盯的是「这个关键词当前的价格」，不是某一件具体商品。同一个关键词今天的最低价可能来自 A 店，明天来自 B 店。

想盯准某一件商品，把标题里最有辨识度的部分当关键词（如 `AMD 9700X 盒装`），越具体越准。

### 二、价格口径

取搜索页商品条目里的 `price` 字段（整数分），即搜索列表上显示的拼单价。

不含券。H5 搜索页不下发券后价，要拿到精确到手价只能逐件进商品详情页，请求量会放大几十倍。因此：

- 有店铺券、平台券的商品，实际到手可能比记录的价格更低
- 百亿补贴、新人价等个性化优惠不完全体现在列表价里

这些偏差对所有监控项一致，不影响「较昨日涨跌」和「是否刷新史低」的判断，只是绝对值可能略高于最终支付金额。

### 三、价格离群剔除

搜索页一次会返回二三十条商品。里面除了目标商品，还混着一批**标题也含这个关键词、但根本不是一类东西**的条目——外设、配件、引流 SKU：

```
¥3.99    CPU 散热器 通用 硅脂 导热膏
¥19.90   AM5 扣具 底座 9700X 兼容
¥89      9700X 散热器 六热管 静音风扇
¥139     9700X 机箱 侧透 ATX 中塔
¥1109    锐龙5 7500F/9600X/9700X 选配
¥1180    AMD 锐龙7 9700X 盒装 全新 正品      ← 真正要盯的
¥1382    锐龙 9700X 散片 三年质保
¥1458.50 AMD 锐龙7 9700X 盒装 二手拆机
¥1580    锐龙7 9700X 主板 CPU 套装
¥1690    AMD 锐龙9 9950X 盒装
```

注意前四条：标题里连「配件」「兼容」这种提示词都没有（`9700X 散热器`、`9700X 机箱`），单靠分词比对分不出来——它们和正品一样完整命中了 `9700X`。所以插件在匹配标题**之前**先做一次价格初筛，把明显离群的低价条目剔掉，再进匹配。

算法是**对数空间的中位数绝对偏差（MAD）**，只剔下限：

1. 取所有价格的中位数当基准
2. 算每条价格偏离中位数多远，再取这些偏离值的中位数，作为「正常波动范围」
3. 低于 `中位数 − k × 波动范围` 的判定为离群，剔除；高于中位数的一律保留

上例 10 条的中位数约 ¥1144，下限落在 ¥392：前四条被剔掉，剩下六条进入标题匹配。

| 设计选择        | 原因                                                                    |
| ----------- | --------------------------------------------------------------------- |
| 用对数，不用原始价格  | 商品价格右偏，¥4 和 ¥3000 差 750 倍。线性尺度下几个高价就能把阈值撑得很宽，结果一条低价配件都剔不掉          |
| 用 MAD，不用标准差 | 标准差会被离群点自己带偏：越离谱的点越会把阈值推开，反而剔不掉。MAD 只看「偏离中位数多远」，对少量配件混进一堆正品最灵敏 |
| 用 MAD，不用 IQR | IQR 的价格窗口在跨度大时过宽（1.5 倍 IQR 实测一条都剔不掉），对这类场景不适用                          |
| 只剔下限，不剔上限   | 目标是取最低价，贵的（套装、多件装）不影响结果，剔了反而误伤。单边剔除还避开了「配件比正品还多时，把少量正品当离群剔掉」这个致命误判 |

两道保护：**样本少于 6 条**不做剔除（统计量不可靠）；**剔除后剩余不足 15%** 视为剔除过度，放弃剔除、按原样处理。

`/盯价 debug` 里对应这一行：

```
过滤：剔除 4 条低价离群，保留 6/10 条（下限 ¥392.47）
```

没有可剔的条目时显示「价格分布连续，没有可剔除的离群项」；样本太少时显示「仅 N 条，样本太少不做剔除」。

严格程度由 `outlier_k` 控制，默认 3。这个值不影响请求次数，只改本地阈值。

### 四、标题匹配

初筛之后剩下的基本是同一品类了，但同品类内部仍有差别：选配 SKU、散片、二手、拆机，价格能差出好几成。这一步按标题分词比对，选出和你的关键词最像的那一条：

1. 关键词分词 → 关键词词集
2. 取价格最低的前 N 条（`title_match_top_n`）商品，标题各自分词
3. 算重合度 = 交集词数 ÷ 关键词词数
4. 标题里出现「配件」「兼容」「选配」这类词、而关键词本身没有时，重合度打对折（降权）
5. 取打分最高的那条作为价格参考
6. 次低取它后面的两条

上例中关键词 `AMD 9700X 盒装` 切成 `{amd, 9700x, 盒装}`，剔除离群后剩六条，取前 5 条比对：

| 商品                         | 交集           | 重合度       | 降权后       |
| -------------------------- | ------------ | --------- | --------- |
| 锐龙5 7500F/9600X/9700X 选配   | 9700x        | 33%       | 17%（选配）   |
| **AMD 锐龙7 9700X 盒装 全新 正品** | amd、9700x、盒装 | **100%**  | **100%** ← 选中 |
| 锐龙 9700X 散片 三年质保           | 9700x        | 33%       | 33%       |
| AMD 锐龙7 9700X 盒装 二手拆机      | amd、9700x、盒装 | 100%（同分，更贵） | 100%      |
| 锐龙7 9700X 主板 CPU 套装        | 9700x        | 33%       | 33%       |

结果是底价 ¥1180，次低 ¥1382、¥1458.50。

规则细节：

- **平局**：打分相同 → 命中词更多的优先 → 仍相同则取价格更低的
- **型号不切碎**：jieba 会把 `9700X` 切成 `9700` + `X`，插件另外用正则把型号整串补进词集，所以 `9700X` 命中 3 个词、`9700K` 只命中 1 个，不会互相混淆
- **降权不改展示分**：`/盯价 debug` 显示的是原始重合度，另标「含配件词已降权」，不会出现「明明全命中却显示 50%」
- **兜底**：前 N 条一条都没命中关键词、或关键词分不出有效词（如只填标点）时，退回取最低价，不报错
- **没有 jieba**：退化成子串匹配，`/盯价 debug` 会标明「子串匹配」

## 让请求更像浏览器（可选）

插件默认只伪造请求头。装上 `curl_cffi` 后，TLS 握手与 HTTP/2 帧序也会伪装成 Safari——这是平台风控最常看、也最难伪造的一层。

```
pip install curl_cffi
```

装完不用改配置，`transport` 默认 `auto` 会自动启用。Docker 部署注意装进容器。

验证方式：`/盯价 debug 纸巾` 最后两行。装上后是

```
传输：curl_cffi/safari_ios（TLS + HTTP2 指纹已模拟）
UA：默认、iPhone Safari
```

没装则是

```
传输：httpx（仅伪造请求头，TLS 指纹仍是 Python 默认值）
```

`user_agent` 建议填成取 Cookie 那台手机的 UA，与 Cookie 绑定的设备保持一致。获取方法：手机浏览器访问 `javascript:document.body.innerText=navigator.userAgent`，复制整行填入。

> 这类手段只是降低概率。平台风控还看账号活跃度、历史行为、IP 归属，那些插件无法干预。**用日常在用的主号，比任何伪装都有效。**

## 故障排查

单个关键词取不到价时执行：

```
/盯价 debug 纸巾
```

正常输出：

```
「纸巾」搜到 38 条
过滤：剔除 5 条低价离群，保留 33/38 条（下限 ¥3.20）
当前最低：¥8.79
　32大包/整箱家用抽纸办公室面巾纸动漫餐巾纸抽酒店宿舍卫生纸巾
　商品 955881402789
匹配：前 5 条里第 1 条 · 重合 100%（命中 纸巾、抽纸）
排序：price（升序）
cookie：218 字符、含 PDDAccessToken、含 pdd_user_id
会话：已沿用 6 个服务端下发的设备 cookie
传输：curl_cffi/safari_ios（TLS + HTTP2 指纹已模拟）
UA：默认、iPhone Safari
```

失败时输出原因：

| 输出                        | 含义             | 处理                   |
| ------------------------- | -------------- | -------------------- |
| `未配置 cookie…`             | 配置项为空          | 按「配置 Cookie」粘贴       |
| `搜索页返回「系统繁忙」，账号被限流`       | 账号被限流          | 等待恢复；换主号或换网络         |
| `搜索页要求验证码验证，账号被风控`        | 触发滑块验证         | 用手机打开拼多多手动过一次验证，或换账号 |
| `搜索页没有下发行情数据（rawData 缺失）` | Cookie 失效或页面改版 | 重新取 Cookie；仍报错见下     |
| `页面结构能解析，但没找到商品列表`        | 该词确实没有结果       | 换个更宽的词试试             |
| `搜到 N 件商品，但没有一件能解析出价格`    | 价格字段改名         | 升级插件                 |
| `页面返回 HTTP 403`           | 被 IP 层拦截       | 换网络环境                |
| `网络请求失败：…`                | 超时或 DNS/代理问题   | 检查 AstrBot 所在机器的网络   |
| `cookie：缺 PDDAccessToken` | 复制的是未登录 Cookie | 登录后再取一次              |

`页面结构能解析，但没找到商品列表` 最常见，多数情况是这个关键词确实没有结果。换成「纸巾」再试一次——能出价说明插件和 Cookie 都正常，是那个词本身没货。

### 风控与退避

命中「系统繁忙」「验证码」这类平台限流时，插件会**立即中止本轮巡检**，不再请求其余关键词；`/盯价 check` 显示「本轮已中止：…」。已有价格不会被清空。

随后进入指数退避：第 1 次冷却 1 小时，第 2 次 2 小时，第 3 次 4 小时，到 `risk_backoff_max_hours`（默认 8 小时）封顶。冷却期内不会提前开始下一轮巡检。

连续第 2 次命中时推送提醒：

```
【盯价暂停】
拼多多搜索页连续限流，已冷却 120 分钟后再试。
限流按账号算，频繁重试会越限越久。换网络或换账号通常能恢复。
```

恢复后推送「【盯价恢复】」并清零计数。

> 拼多多的限流是账号级的，不是 IP 级。同一个 IP 换个已登录的主号通常立刻恢复；同一个号换 IP 往往无效。

## 数据与隐私

- 存盘位置：`data/plugin_data/astrbot_plugin_pdd_monitor/pdd_price.json`
- 内容：监控项、每日价格快照、推送会话列表、服务端下发的设备 Cookie
- 写入方式：临时文件 + `os.replace` 原子替换
- **不存**页面原文，**不存**登录态 Cookie（`PDDAccessToken` 等三个字段永远只从配置读取）
- 文件带 `data_version` 字段；价格口径变更时会升级版本，读到旧版本文件会清空监控与历史（保留推送会话列表）

单个监控项记录：关键词、当前最低价商品（标题 / 商品 id / 链接）、最近一次搜索的最低 3 条、现价、历史最低价及时间、每日快照、连续失败次数与最近错误。

## 已知限制

- **价格不含券**：见「取价规则 · 价格口径」。
- **盯关键词不盯商品**：最低价可能来自不同店铺，史低提醒里会标注商品标题与 id 便于判断。
- **只看搜索页第一页**：30~60 条。带价格升序时这一页就是最便宜的一批，但不是全站绝对最低价。
- **依赖 Cookie**：换账号登录、退出登录、长时间不活跃都会让它失效，需要手动更换。
- **两层过滤都有边界**：标题匹配依赖卖家把型号写进标题（写成「处理器 8 核 全新」就对不上），离群剔除依赖「配件明显比正品便宜」这个前提（配件与正品同价时剔不掉）。遇到这类词，把关键词写具体比调参数有效。
- **风控是账号级的**：被限流后只能等待或换号，插件能做的是中止本轮并退避。
- **主动消息**：个人号 QQ（aiocqhttp）、Telegram、飞书支持主动推送；QQ 官方接口、企业微信、钉钉不支持，只能通过「今日行情」被动查询。

## 常见问题


| 现象                   | 原因与处理                                                          |
| -------------------- | -------------------------------------------------------------- |
| 提示未配置 cookie         | 插件配置里没填，填好后重载插件                                                |
| 全部关键词报「系统繁忙」         | 账号被限流。换主号，或等几小时；退避机制会自动恢复                                      |
| 全部关键词报「rawData 缺失」   | Cookie 失效或粘的是未登录 Cookie，重新取一条                                  |
| 换了账号后立刻好了            | 印证限流是账号级的，不是插件问题                                               |
| 某个关键词一直搜不到商品         | 该词本身没货。换成「纸巾」验证插件是否正常                                          |
| 记下的价格明显偏低（像配件价）      | 先看 `/盯价 debug` 的「过滤」行：没剔掉离群项时把 `outlier_k` 调到 2；再看「匹配」行，把 `title_match_top_n` 调大，或换个更具体的词 |
| `/盯价 debug` 显示「子串匹配」 | 没装 jieba，`pip install jieba` 后重启                               |
| 价格比 App 里看到的略高       | 列表价不含券，App 里可能叠了店铺券或补贴                                         |
| 价格每次都在小幅跳动           | 搜索结果的商品集合本身在变，最低价来自不同店铺，属正常现象                                  |
| 群内收不到史低推送            | 群内执行一次 `/盯价 on`；或该平台不支持主动消息                                    |
| 更新插件后数据没了            | 价格口径变更导致 `data_version` 升级，旧数据被清空属预期行为                         |
| Cookie 好像泄露了         | 到拼多多 App 退出登录再重新登录，旧 Cookie 立即失效                               |

## 与对话上下文的关系

- 不调用任何 LLM 接口，不消耗 token，不写入会话历史。
- 指令回复与史低推送是平台层消息，不进入 AstrBot 会话上下文。
- 「今日行情」监听器仅在短问句命中时接管消息，其余直接放行给 LLM：
  - `今日行情`、`@机器人 今天行情` → 接管
  - `帮我把今日行情做成表格` → 放行（剥离触发词后超过 6 字）
  - 群内未 @机器人 → 不接管
- 已识别插件自身消息，避免平台回显导致自问自答。
