# 多多盯价

按关键词监控拼多多搜索结果的最低价。刷新历史最低价时推送至已绑定的会话；群内 @机器人 说「今日行情」查询全部监控项的现价与涨跌。

| 项目     | 值                                                       |
| ------ | ------------------------------------------------------- |
| 插件目录名  | `astrbot_plugin_pdd_monitor`                            |
| 数据目录   | `data/plugin_data/astrbot_plugin_pdd_monitor/`          |
| 依赖     | `playwright`（含 Chromium 内核）、`jieba`、`httpx`、`curl_cffi` |
| AstrBot | ≥ 3.4.28                                                |

---

## 特性

| 功能     | 说明                                |
| ------ | --------------------------------- |
| 关键词监控  | 一条指令添加一个关键词，不需要商品链接               |
| 浏览器取数  | 启动无头 Chromium 取数，绕开搜索页的请求签名与响应加密 |
| 定时巡检   | 默认 30 分钟一轮，请求串行、间隔随机              |
| 离群剔除   | 匹配前先剔掉价格离群的配件、外设                  |
| 标题匹配   | 按分词重合度选出真正要对标的那一件                 |
| 史低推送   | 刷新历史最低价时推送至已绑定的会话                 |
| 今日行情   | 查询现价、较昨日涨跌、历史最低价                  |
| 每日播报   | 可选，在指定时间自动推送一次行情                  |
| 风控退避   | 平台拒绝时自动冷却，不连续请求                   |
| 取价诊断   | 输出单个关键词的取价明细与失败原因                 |

## 安装

1. 将 `astrbot_plugin_pdd_monitor` 整个目录放入 AstrBot 的 `data/plugins/`。
2. 在 WebUI 插件管理页重载插件，或重启 AstrBot。首次加载自动安装 `requirements.txt` 中的依赖。
3. 填写 `cookie` 配置项，见「配置 Cookie」。
4. 在群内发送 `/盯价 add 纸巾` 验证。

### 浏览器内核

`pip` 只安装 `playwright` 这个 Python 包，Chromium 内核需要单独下载（一百多 MB）。内核缺失时插件不会启动失败，而是在首次取数时自动执行：

```bash
python -m playwright install chromium
```

下载进度输出到 AstrBot 日志，完成后自动继续启动浏览器，无需重启插件。由 `browser_auto_install` 控制，默认开启。

关闭该开关、或自动下载失败时，需手工执行上述命令。Linux 上若启动报缺少系统库，再补一行：

```bash
python -m playwright install-deps chromium
```

`browser_channel` 填写系统浏览器（`chrome`、`edge`）时不触发自动下载，该配置项指向的是系统已安装的浏览器，`playwright install` 不负责安装它。

内核是否就绪，看 `/盯价 debug <关键词>` 的「取数」行：

```
取数      浏览器 · chrome-headless-shell（已启动）
取数      浏览器 · chrome-headless-shell（未启动，首次取数时拉起）
取数      浏览器 · chrome-headless-shell（进程已退出，下次取数时自动重启）
取数      浏览器 · chrome-headless-shell（已启动） · 已自动补装内核
```

最后一种表示该次取数前刚下载完内核。

### 为什么需要浏览器

搜索页为客户端渲染：服务端返回的 HTML 只有空骨架，商品数据由页面 JS 通过 XHR 拉取后解密、再渲染。

- 请求需要 `anti_content` 签名（606 字符），由页面 JS 现算，带时效。
- 响应体是 `rc-res-data` 网关密文（十万字符），解密器位于按需加载的 chunk 中。

签名与解密均在浏览器环境内完成。插件因此启动一个无头 Chromium 执行完整页面流程，再读取内存中解密后的对象。相比解析 HTML，该方式直接取得 `goods_id`、价格原值、销量等字段，也不受页面改版更换类名影响。

`fetch_mode` 保持默认 `browser` 即可。`http` 为旧路线（抓取 HTML 提取 `window.rawData`），搜索页改为客户端渲染后基本取不到价，保留用于排查；`auto` 先试 `http`，取不到再转浏览器，代价是多一次请求。

### 从 v3 升级

覆盖目录后重载插件。`cookie`、`proxy`、已有监控项均保留。注意事项：

1. 首次取数会触发内核下载。若希望提前完成，按上文手工执行一次。
2. 新增配置项按默认值生效，旧配置文件缺少该键时不需要补写。
3. `fetch_mode` 可改回 `http` 或 `auto`，旧路线未删除。

## 配置 Cookie

`cookie` 是唯一必填项，必须为**已登录**状态的拼多多 Cookie。缺失时搜索页只返回不含商品的空壳页。

### 手机端获取

1. 手机浏览器打开 `https://mobile.yangkeduo.com/`，登录。
2. 搜索任意词（如「纸巾」），确认商品列表正常显示。
3. 地址栏将当前网址替换为下列内容后回车，页面显示整条 Cookie：
   ```
   javascript:document.body.innerText=document.cookie
   ```
   部分浏览器会过滤 `javascript:` 前缀，可先手动输入 `java` 再粘贴其余部分。
4. 全选页面文字并复制。

### 电脑端获取

1. 浏览器打开 `https://mobile.yangkeduo.com/`，扫码登录。
2. 按 `F12` 打开开发者工具，切至 **Network（网络）** 面板。
3. 刷新页面，点选任意一条 `mobile.yangkeduo.com` 请求。
4. 在 **Headers → Request Headers** 中找到 `Cookie:`，复制其后的整条值。

### 粘贴

整段粘贴至 `cookie` 配置项，无需手工清理。以下形态均由插件自动处理：

- 带 `Cookie:` 或 `cookie：` 前缀
- 从开发者工具整段复制，夹带 `Host:`、`User-Agent:` 等其他请求头
- 长 Cookie 被折成多行
- 首尾带引号或分号

验证方法：执行 `/盯价 debug 纸巾`，输出中有一行

```
cookie    218 字符 · 11 个字段 · 含 PDDAccessToken
```

显示 `缺 PDDAccessToken` 表示复制的不是登录态 Cookie（通常为未登录时的匿名 Cookie），重新登录后再取一次。

### 账号要求

- **使用日常在用的主号。** 风控按账号计算，新注册小号、长期不登录的号，搜索页通常直接返回「系统繁忙」。
- Cookie 等同于账号登录凭证，不应粘贴到聊天、截图或公开仓库。插件只将其放入请求头，不写入日志、数据文件或聊天回复。
- 换设备登录、退出登录、修改密码均会使旧 Cookie 失效。届时 `/盯价 debug` 开始报错，重新取一条即可。

## 配置项

| 键                         | 类型     | 默认           | 说明                                            |
| ------------------------- | ------ | ------------ | --------------------------------------------- |
| `cookie`                  | string | 空            | 拼多多网页 Cookie，必填，须含 `PDDAccessToken`           |
| `user_agent`              | string | 空            | 留空用内置 iPhone Safari UA；填取 Cookie 那台手机的 UA 最安全 |
| `proxy`                   | string | 空            | 出口代理，格式 `http://host:port` 或 `socks5h://user:pass@host:port`；部署在云服务器上必填 |
| `fetch_mode`              | string | `browser`    | `browser` 浏览器取数 / `http` 旧路线 / `auto` 先试 HTTP 再转浏览器 |
| `browser_channel`         | string | 空            | 留空用默认无头壳；填 `chromium` 用完整内核                     |
| `browser_headless`        | bool   | true         | 无头运行；服务器无桌面环境时保持开启                            |
| `browser_timeout`         | int    | 45           | 浏览器取数超时（秒），走内网穿透时调至 60~90                     |
| `browser_auto_install`    | bool   | true         | 内核缺失时自动执行 `playwright install chromium`      |
| `transport`               | string | `auto`       | 仅 `fetch_mode=http` 时生效，自动用 curl_cffi 伪装 TLS 指纹 |
| `impersonate`             | string | `safari_ios` | 仅 `fetch_mode=http` 时生效                       |
| `warmup_home`             | bool   | true         | 首轮巡检前先访问一次首页，获取基础设备 Cookie                    |
| `search_sort`             | string | `price`      | 搜索页排序：`price` 升序 / `_price` 降序                |
| `keyword_filter_by_title` | bool   | true         | 按标题分词匹配选品；关闭则始终取最低价                           |
| `title_match_top_n`       | int    | 5            | 参与比对的前 N 条商品，1~20                             |
| `filter_price_outliers`   | bool   | true         | 匹配前先剔除价格离群的商品；关闭则全部参与匹配                       |
| `outlier_k`               | int    | 3            | 离群剔除严格程度，1~6，越小越严格                            |
| `outlier_drop_percent`    | int    | 30           | 价格闸门：低于中位数该百分比才允许被剔                        |
| `check_interval_minutes`  | int    | 30           | 巡检间隔（分钟）                                      |
| `request_timeout`         | int    | 15           | 单次页面请求超时（秒），仅 `fetch_mode=http` 时生效           |
| `notify_at_new_low`       | bool   | true         | 是否推送史低提醒                                      |
| `max_goods`               | int    | 50           | 最多监控的关键词数量                                    |
| `daily_report_time`       | string | 空            | 每日自动播报时间，如 `20:00`；留空关闭                       |
| `risk_backoff_max_hours`  | int    | 8            | 触发限流后的最长冷却时间（小时）                              |

**`search_sort`** 保持默认 `price`。改为 `_price`（降序）后第一页为最贵的一批商品，在其中取最小值将得到虚高的「最低价」。

**`title_match_top_n`** 只影响本地比对范围，不影响请求次数——所有候选商品都在同一次搜索响应内，取 5 条或 20 条对风控无区别。调大可能纳入价格高出较多的商品，调小可能排除真正匹配的那条。

**`outlier_drop_percent`** 为 MAD 剔除之外的比例闸门，默认 30。作用见「取价规则 · 价格离群剔除」。填 100 等于关闭该闸门、完全交给 MAD。

**`browser_timeout`** 为打开搜索页到截获商品数据的总时限。走内网穿透时链路经家用宽带绕行，比直连慢，家中上行带宽较小时调至 60~90 更稳。超时报错会写明原因（跳登录页 / 系统繁忙 / 未截到明文）。

**`filter_price_outliers`** 与 **`outlier_k`** 控制匹配前的初筛，见「取价规则 · 价格离群剔除」。默认值 3 只剔比中位数低一大截的条目：调至 1~2 更严格，可能连带剔除便宜的二手、拆机件；调至 5~6 更宽容，只剔差数十倍的极端项。`keyword_filter_by_title` 关闭时该层仍然生效。

**`check_interval_minutes`** 不建议低于 20。监控项较多时调大更稳。

## 输出格式

所有回复与推送采用同一体例。

**首行**为 `【多多盯价】` + 动作，必要时以 ` · ` 追加对象或状态：

```
【多多盯价】已添加
【多多盯价】诊断 · 纸巾
【多多盯价】已删除 · 9700X
【多多盯价】未找到 · 9 · /盯价 list 查序号
```

**正文**为两列，标签按显示宽度补齐，值左对齐：

```
关键词    9600X
现价      ¥1049.00
史低      ¥1049.00 · 首次记录
```

**多条记录**（今日行情、监控列表）不使用列对齐，改为一项一行、以空格和 ` · ` 分隔：

```
1 纸巾 ¥8.79 ▼¥1.11 ★
2 蓝牙耳机 ¥11.90 ▲¥3.00 · 史低 ¥8.90
```

原因：手机 QQ 一屏只放得下二十来个汉字，补空格对齐的表格一折行就整列错位，对齐越整齐越难读。一项一行时，折行只影响该项自身，后续各项仍从新行开始。关键词较长的项（如 `RTX5070ti 显卡`）会折成两行，属预期行为。同理，所有汇总信息（统计、图例、提示）各自独立成行，不并排堆叠。

**错误**统一为三段，用 `｜` 分隔：现象、原因、处理。诊断输出中会拆成三行显示。

```
搜到 0 条商品｜store.data.ssrListData.list 为空｜只留型号重试：/盯价 debug 5070ti
```

不带数据的回执为单行 `【多多盯价】动作 · 对象`。

## 取价规则

### 一、监控对象是关键词

插件不识别商品链接，只识别关键词。监控的是「该关键词当前的价格」，不是某一件具体商品；同一个关键词今天的最低价可能来自 A 店，明天来自 B 店。

需锁定某一件商品时，将标题中最有辨识度的部分作为关键词（如 `AMD 9700X 盒装`），越具体越准。

关键词中的空格表示「同时包含」：`rx7800xt 花嫁` 要求标题中同时出现 `rx7800xt` 与 `花嫁`。词越多越准，但也越容易搜不到——卖家标题不一定写全系列名、后缀、缩写。典型搜不到的例子：`5070ti ultra w oc`（单独一个 `w` 几乎不作为词出现在标题中）、`amd rx9070xt 氪动极光`（系列名写错则整串落空）。

搜不到时 `/盯价 debug` 会说明搜到 0 条，并给出只留型号的短版本：

```
【多多盯价】诊断失败 · 5070ti ultra w oc
现象      搜到 0 条商品
原因      store.data.ssrListData.list 为空
处理      只留型号重试：/盯价 debug 5070ti
```

这与「页面能解析但没有任何列表」是两种情况：后者说明页面连列表都未下发，属 Cookie 失效或页面改版。

### 二、价格口径

取搜索页商品条目的 `price` 字段（整数分），即搜索列表显示的拼单价。

不含券。H5 搜索页不下发券后价，取得精确到手价需逐件进入商品详情页，请求量将放大数十倍。因此：

- 有店铺券、平台券的商品，实际到手价可能低于记录值
- 百亿补贴、新人价等个性化优惠不完全体现在列表价中

该偏差对所有监控项一致，不影响「较昨日涨跌」与「是否刷新史低」的判断，仅绝对值可能略高于最终支付金额。

### 三、价格离群剔除

搜索页一次返回二三十条商品，其中混有**标题同样包含该关键词、但并非同类**的条目：外设、配件、引流 SKU。

```
¥3.99    CPU 散热器 通用 硅脂 导热膏
¥19.90   AM5 扣具 底座 9700X 兼容
¥89      9700X 散热器 六热管 静音风扇
¥139     9700X 机箱 侧透 ATX 中塔
¥1109    锐龙5 7500F/9600X/9700X 选配
¥1180    AMD 锐龙7 9700X 盒装 全新 正品      ← 目标商品
¥1382    锐龙 9700X 散片 三年质保
¥1458.50 AMD 锐龙7 9700X 盒装 二手拆机
¥1580    锐龙7 9700X 主板 CPU 套装
¥1690    AMD 锐龙9 9950X 盒装
```

前四条标题中不含「配件」「兼容」等提示词（`9700X 散热器`、`9700X 机箱`），分词比对无法区分——它们与正品一样完整命中了 `9700X`。因此插件在标题匹配**之前**先做一次价格初筛，剔除明显离群的低价条目。

算法为**对数空间的中位数绝对偏差（MAD）**，只剔下限：

1. 取全部价格的中位数作为基准
2. 计算每条价格偏离中位数的幅度，再取这些幅度的中位数，作为「正常波动范围」
3. 低于 `中位数 − k × 波动范围` 的判为离群并剔除；高于中位数的一律保留

上例 10 条的中位数约 ¥1144，下限落在 ¥392：前四条被剔除，其余六条进入标题匹配。

| 设计选择      | 原因                                                                   |
| --------- | -------------------------------------------------------------------- |
| 用对数，不用原始价格 | 商品价格右偏，¥4 与 ¥3000 相差 750 倍。线性尺度下几个高价即可将阈值撑宽，结果一条低价配件都剔不掉       |
| 用 MAD，不用标准差 | 标准差受离群点影响：越离谱的点越会把阈值推开，反而剔不掉。MAD 只看「偏离中位数多远」，对少量配件混入大量正品最灵敏   |
| 用 MAD，不用 IQR | IQR 的价格窗口在跨度大时过宽（1.5 倍 IQR 实测一条都剔不掉），不适用此场景                        |
| 只剔下限，不剔上限 | 目标是取最低价，贵的（套装、多件装）不影响结果，剔除反而误伤。单边剔除也避开了「配件多于正品时把少量正品当离群」这一误判 |

两道保护：**样本少于 6 条**不做剔除（统计量不可靠）；**剔除后剩余不足 15%** 视为剔除过度，放弃剔除、按原样处理。

`/盯价 debug` 中对应「过滤」行：

```
过滤      剔除 4 条低价离群 · 保留 6/10 · 下限 ¥392.47
```

无可剔条目时显示「价格分布连续，没有可剔除的离群项」；样本不足时显示「仅 N 条，样本太少不做剔除」。

#### 比例闸门

仅靠 MAD 存在误伤，且误伤隐蔽。实测搜索「9600X」返回 20 条，其中 18 条为「CPU + 主板」套装，集中在 ¥1645～1899：

```
¥1049    【AMD】锐龙5 9600X盒装 全新未拆封        ← 裸 CPU，目标商品
¥1459    【AMD】9000系新品 9600X 9700X 盒装
¥1479    【AMD】9000系新品 9600X 9700X 盒装
¥1549    AMD 9600X散片 搭 微星 PRO B650M-P
¥1645    【七彩虹】B850M GAMING FROZEN + AMD 96...
   ...   其后全为同类套装，直至 ¥1899
```

套装价格集中，MAD 算出的波动范围极小，下限贴至 ¥1570——**¥1049 的裸 CPU 反而成为统计学意义上的离群值**被剔除，输出的「最低价」变为 ¥1645，而实际存在 ¥1049。

因此剔除条件增加一道闸门：**仅当价格低于「中位数 × 30%」时才允许被剔**。

- ¥3.99 的导热膏 vs 中位数 ¥1144：占 0.3%，剔除
- ¥1049 的裸 CPU vs 中位数 ¥1800：占 58%，保留

闸门由 `outlier_drop_percent` 控制，默认 30。填 50 会将上述 ¥1049 一并剔除；填 5 更严格，仅剔差 20 倍以上者；填 100 等于关闭闸门。

严格程度由 `outlier_k` 与 `outlier_drop_percent` 两个参数控制，默认 3 与 30，均不影响请求次数，只改本地阈值。

### 四、标题匹配

初筛后的商品基本属同一品类，但品类内部仍有差别：选配 SKU、散片、二手、拆机，价格可相差数成。此步按标题分词比对，选出与关键词最接近的一条。

1. 关键词分词，得到关键词词集
2. 取价格最低的前 N 条（`title_match_top_n`），标题各自分词
3. 计算重合度 = 交集词数 ÷ 关键词词数
4. 标题含「配件」「兼容」「选配」等词、而关键词本身不含时，重合度对折（降权）
5. 取分值最高者作为价格参考
6. 次低取其后的两条

上例中关键词 `AMD 9700X 盒装` 切为 `{amd, 9700x, 盒装}`，剔除离群后剩六条，取前 5 条比对：

| 商品                        | 交集          | 重合度        | 降权后         |
| ------------------------- | ----------- | ---------- | ----------- |
| 锐龙5 7500F/9600X/9700X 选配  | 9700x       | 33%        | 17%（选配）     |
| **AMD 锐龙7 9700X 盒装 全新 正品** | amd、9700x、盒装 | **100%**   | **100%** ← 选中 |
| 锐龙 9700X 散片 三年质保          | 9700x       | 33%        | 33%         |
| AMD 锐龙7 9700X 盒装 二手拆机     | amd、9700x、盒装 | 100%（同分，更贵） | 100%        |
| 锐龙7 9700X 主板 CPU 套装       | 9700x       | 33%        | 33%         |

结果为底价 ¥1180，次低 ¥1382、¥1458.50。

规则细节：

- **平局**：分值相同则命中词更多的优先，仍相同则取价格更低者
- **型号不切碎**：jieba 会把 `9700X` 切成 `9700` + `X`，插件另以正则将型号整串补入词集，因此 `9700X` 命中 3 个词、`9700K` 只命中 1 个，不会互相混淆
- **降权不改展示分**：`/盯价 debug` 显示原始重合度，另标「含配件词已降权」
- **兜底**：前 N 条均未命中关键词、或关键词无法分出有效词（如仅填标点）时，退回取最低价，不报错
- **无 jieba**：退化为子串匹配，`/盯价 debug` 中标注「子串匹配」

## 浏览器环境

TLS、HTTP/2、JS 引擎、Canvas、字体、触摸支持均由 Chromium 自身生成，无需另行构造指纹。插件额外处理两项：

- 关闭 `AutomationControlled` 特征，并将 `navigator.webdriver` 置为 `undefined`（无头浏览器最易被识别的标记）
- 使用 iPhone UA + 440×956 视口 + `is_mobile`，三者须同时设置。缺一项即落入「系统繁忙」——桌面 UA 访问移动站是该页面最典型的拒绝方式

`curl_cffi` 仍保留在依赖中，仅在 `fetch_mode=http` 时使用（该路线基本取不到价，保留用于排查与应急）。

`user_agent` 留空时使用内置 iPhone Safari UA。填为取 Cookie 那台手机的 UA 与设备标识更一致，获取方法：手机浏览器访问 `javascript:document.body.innerText=navigator.userAgent`，复制整行填入。

> 上述手段只降低概率。平台风控同时考察账号活跃度、历史行为、IP 归属，插件无法干预。**使用日常在用的主号，比任何指纹伪装都有效。**

## 出口 IP

**症状**：同一账号在本机浏览器中可正常搜索，但部署在阿里云、腾讯云等机房的机器人始终返回「系统繁忙」降级页。Cookie 完整，指纹已伪装，仍无效。

**原因**：平台除账号与指纹外，还判断请求来源 IP 段。机房 IP 归属为云厂商 ASN，天然带「服务器」标签，而爬虫绝大多数运行在云端。家用宽带、手机流量为住宅 ASN，信任度不同。**此类拒绝不是封号，等待不会恢复，换账号亦无效——变的是 IP，不是身份。**

判断方法：确认浏览器与机器人是否使用同一出口 IP。不同则优先怀疑该层。

**解法**：为 `proxy` 配置项填入住宅出口。

```
http://host:port
http://user:pass@host:port
socks5h://user:pass@host:port    # 走内网穿透时优先
socks5://user:pass@host:port     # 域名在客户端先解析为 IP 再发往代理
```

`socks5h` 与 `socks5` 的区别仅在**由谁做 DNS**：

- `socks5h://` —— 域名原样送至代理端，由代理解析。**优先使用**：出口 IP 与 DNS 均来自同一条家宽，结果与真实浏览器一致，也可避免客户端解析到 IPv6 而代理不通。
- `socks5://` —— 客户端先将域名解析为 IP，再以 IP 形式发往代理（常见为 IPv6）。自建代理若限制 IP 直连，会在此被拒。

来源按可行性排序：

1. **自有家宽**——路由器端口映射，或在局域网运行 HTTP 代理（`tinyproxy`、`squid`）后映射出去。免费且为真实家宽 ASN，最稳。
2. **手机热点 / 随身 WiFi**——同理，走移动网络 ASN。
3. **住宅代理服务**——按流量计费，选择国内住宅 IP，注意合规与稳定性。

### 内网穿透的三个问题

**其一：隧道类型须为 `tcp`。** `http` 类型隧道为虚拟主机模式，按 `Host` 路由，只接受 `GET`/`POST`，代理的 `CONNECT` 请求会被回 `501`。

**其二：部分服务商对隧道做 HTTP 内容合规检测，会拦截明文 HTTP 流量。** 隧道日志显示「TCP 隧道启动成功」，但客户端收到的是服务商错误页：

```
HTTP/1.1 501 Not Implemented
Server: SakuraFrp
```

页面正文提示「您正试图使用 HTTP 协议访问此隧道……请启用 HTTPS 后访问」。此时更换隧道类型、线路、端口均无效，因为拦截依据是**协议**而非隧道配置。

**解法：改用 SOCKS5。** SOCKS5 握手为二进制（`\x05\x01\x00`），不构成 HTTP 请求，不被此类规则命中。将代理端点改为 SOCKS5 后：

```
socks5h://user:pass@节点域名:远程端口
```

应写 `socks5h` 而非 `socks5`。`socks5://` 会让客户端先解析域名，若解析到 IPv6 而代理只监听 IPv4 出口，会在握手末步被拒。`socks5h://` 交由代理端解析，绕开此类问题。

自建代理时同时监听 HTTP 与 SOCKS5 最省事：按首字节 `0x05` 分流即可。

**其三：Chromium 不发送 SOCKS5 用户名密码。** Chromium 的 SOCKS5 握手只声明「免认证」（`0x00`），`socks5://user:pass@host:port` 中的账号密码不会发送；而暴露至公网的代理为安全起见必须带认证，两者不匹配，连接直接失败。

插件已做处理：`proxy` 中带密码时，插件在本机 `127.0.0.1` 启动一个免认证的 SOCKS5 端口，由其携带账号密码连接上游并双向转发。

```
Chromium → 127.0.0.1:随机端口（免认证）→ 本地中继（带认证）→ 隧道 → 上游代理
```

由此可得：

- **不需要**为迁就浏览器将公网代理改为免认证，密码保留；
- 中继只监听回环地址，局域网内其他机器无法连接。上游的域名白名单、端口白名单、内网地址拦截照常生效——中继只代为认证，未放宽任何目标侧限制。

配置完成后执行 `/盯价 debug <关键词>`，「代理」行显示脱敏后的地址：

```
代理      socks5h://pdd:***@frp-van.com:11428
```

该行出现即表示请求确实经代理发出。代理不通时插件会报「网络请求失败」，不会静默直连。

## 故障排查

单个关键词取不到价时执行：

```
/盯价 debug 纸巾
```

输出共 12 行左右，按行判读：

| 行      | 判读                                                                 |
| ------ | ------------------------------------------------------------------ |
| `命中`   | 搜索返回的商品条数。为 0 见下文「搜到 0 条」                                         |
| `过滤`   | 离群剔除结果。`剔除 0 条` 且价格偏低时，将 `outlier_k` 调至 2；`保留 X/Y` 的比值反映剔除强度          |
| `最低`   | 最终采用的价格                                                            |
| `匹配`   | 前 N 条中选中的名次与重合度。显示「未启用」表示 `keyword_filter_by_title` 为 false |
| `cookie` | 长度、字段数、是否含 `PDDAccessToken`。缺字段时给出缺失项                              |
| `取数`   | 取数方式与浏览器进程状态。显示 `httpx` 说明走的是旧路线                                   |
| `代理`   | 脱敏后的出口地址。显示「未配置」且部署在云服务器上时，先怀疑机房 IP                               |
| `快照`   | 仅在失败时出现，为出错页面的源码副本，存放于数据目录 `debug/` 下                              |

失败时首行为 `诊断失败`，`现象`、`原因`、`处理`三行给出结论：

| 现象                         | 原因               | 处理                                     |
| -------------------------- | ---------------- | -------------------------------------- |
| `跳登录页`                     | Cookie 缺失或已失效    | 重新复制整条 Cookie，须含 `PDDAccessToken`      |
| `页面报「系统繁忙」且未截到任何数据包`       | 出口 IP 被限流，或代理未生效 | 查看「代理」行确认生效；仍如此则更换出口                   |
| `页面报「系统繁忙」，但已截到数据包`        | 偶发限流             | 重试一次                                   |
| `没装 playwright`            | 依赖未装             | `pip install playwright`               |
| `内核下载失败` / `内核下载超时`         | 网络或磁盘问题          | 按提示手工执行 `python -m playwright install chromium` |
| `内核下载完仍启动失败`               | 缺系统库             | `python -m playwright install-deps chromium` |
| `页面渲染出 N 个价格，hook 未截到明文`   | 数据不再经 `JSON.parse` | 上报此条等待适配；临时改用 `fetch_mode=http`        |
| `搜到 0 条商品`                 | 该关键词确实无结果        | 按「处理」只留型号，如 `5070ti`                   |
| `搜到 N 件商品，没有一件能解析出价格`     | 价格字段改名           | 上报此条等待适配                               |
| `页面能解析但没有任何列表`            | Cookie 失效或页面改版    | 重新取 Cookie；仍报错则上报                       |
| `平台拒绝了这次搜索`                | 请求特征或 IP 被识别     | 查看「取数」「代理」两行                           |

判据：报错带 `store.data.ssrListData.list 为空` 说明结构未变、该页无商品；带「首条字段：xxx」为改版；带「系统繁忙」为平台拒绝。

`搜到 0 条商品` 最常见，多为关键词过长或型号写错。换成「纸巾」重试：能出价说明插件与 Cookie 均正常，是该词本身无结果。

### 浏览器进程退出

浏览器进程被系统回收（内存不足等）时无需干预。每轮取数前会检查进程存活状态，断开则自动重启后重试一次；仅重启失败时记为一次失败。`/盯价 debug` 的「取数」行会显示「进程已退出，下次取数时自动重启」。

### 风控与退避

命中「系统繁忙」「验证码」等平台拒绝时，插件**立即中止本轮巡检**，不再请求其余关键词；`/盯价 check` 显示「中止」行。已有价格不会被清空。

「系统繁忙」有两种，处理方式相反：

| 现象                | 含义        | 处理                                        |
| ----------------- | --------- | ----------------------------------------- |
| 整页即为「系统繁忙」文字、无数据 | 账号被限流     | 等待数小时；或换号。换号立即恢复则印证为账号级                  |
| 数据仍在、商品列表为空       | 请求被识别为异常客户端 | 依次检查：指纹（取数行）、Cookie 字段（cookie 行）、出口 IP（代理行） |

第二种的典型特征为：**同一账号在浏览器中可正常搜索，仅脚本不可**。等待不会恢复，换账号亦无效——被识别的不是账号，而是该机器的请求特征。

随后进入指数退避：第 1 次冷却 1 小时，第 2 次 2 小时，第 3 次 4 小时，至 `risk_backoff_max_hours`（默认 8 小时）封顶。冷却期内不开始下一轮巡检。

连续第 2 次命中时推送：

```
【多多盯价】巡检暂停
原因      搜索页连续拒绝请求
冷却      120 分钟
恢复      /盯价 reset 立即重试
```

恢复后推送 `【多多盯价】巡检恢复 · 风控计数清零` 并清零计数。

修改配置后不愿等待冷却，执行 `/盯价 reset`：清空风控计数与冷却时间，同时清零各监控项的失败计数，随后可立即 `/盯价 debug` 验证。

> 拒绝分两个层级：**账号级**（浏览器亦不可搜索，换号或等待）与**请求特征级**（浏览器可搜、仅脚本不可，换号无效，需调整指纹或出口）。无法区分时先看「取数」「代理」两行。

- 写入方式：临时文件 + `os.replace` 原子替换
- **不存**页面原文，**不存**登录态 Cookie（`PDDAccessToken` 等三个字段始终只从配置读取）
- 唯一例外为排查用页面快照：仅在手动执行 `/盯价 debug` 且取价失败时写入 `debug/` 子目录，巡检不写。快照为完整页面源码，**不含 Cookie**，排查后可删除
- 文件带 `data_version` 字段；价格口径变更时升级版本，读到旧版本文件会清空监控与历史（保留推送会话列表）

单个监控项记录：关键词、当前最低价商品（标题 / 商品 id / 链接）、最近一次搜索的最低 3 条、现价、历史最低价及时间、每日快照、连续失败次数与最近错误。

## 已知限制

- **价格不含券**：见「取价规则 · 价格口径」。
- **监控关键词而非商品**：最低价可能来自不同店铺，史低提醒中标注商品标题与 id 便于判断。
- **仅取搜索页第一页**：30~60 条。价格升序时该页为最便宜的一批，但不是全站绝对最低价。
- **依赖 Cookie**：换账号登录、退出登录、长时间不活跃均会失效，需手动更换。
- **两层过滤均有边界**：标题匹配依赖卖家将型号写入标题（写作「处理器 8 核 全新」则无法对上）；离群剔除依赖「配件明显便宜于正品」这一前提（配件与正品同价时无法剔除）。此类关键词，写具体比调参数有效。
- **风控为账号级**：被限流后只能等待或换号，插件能做的是中止本轮并退避。
- **主动消息**：个人号 QQ（aiocqhttp）、Telegram、飞书支持主动推送；QQ 官方接口、企业微信、钉钉不支持，只能通过「今日行情」被动查询。

## 常见问题

| 现象                   | 原因与处理                                                          |
| -------------------- | -------------------------------------------------------------- |
| 提示未配置 cookie         | 插件配置中未填，填好后重载插件                                                |
| 全部关键词报「系统繁忙」         | 账号被限流。换主号，或等待数小时；退避机制会自动恢复                                     |
| 全部关键词报「跳登录页」         | Cookie 失效或为未登录 Cookie，重新取一条                                     |
| 换账号后立即恢复             | 印证限流为账号级，非插件问题                                                 |
| 某个关键词一直搜不到商品         | 该词本身无结果。换成「纸巾」验证插件是否正常                                         |
| 记下的价格明显偏低（似配件价）      | 查看 `/盯价 debug` 的「过滤」行：未剔离群项时将 `outlier_k` 调至 2；再查看「匹配」行，将 `title_match_top_n` 调大或换更具体的词 |
| `/盯价 debug` 显示「子串匹配」 | 未装 jieba，`pip install jieba` 后重启                                |
| 价格比 App 中略高          | 列表价不含券，App 中可能叠加店铺券或补贴                                         |
| 价格小幅频繁跳动             | 搜索结果的商品集合本身在变化，最低价来自不同店铺，属正常现象                                 |
| 群内收不到史低推送            | 群内执行一次 `/盯价 on`；或该平台不支持主动消息                                    |
| 更新插件后数据丢失            | 价格口径变更导致 `data_version` 升级，旧数据被清空属预期行为                          |
| Cookie 疑似泄露          | 在拼多多 App 退出登录后重新登录，旧 Cookie 立即失效                                |

## 与对话上下文的关系

- 不调用 LLM 接口，不消耗 token，不写入会话历史。
- 指令回复与史低推送为平台层消息，不进入 AstrBot 会话上下文。
- 「今日行情」监听器仅在短问句命中时接管消息，其余放行给 LLM：
  - `今日行情`、`@机器人 今天行情` → 接管
  - `帮我把今日行情做成表格` → 放行（剥离触发词后超过 6 字）
  - 群内未 @机器人 → 不接管
- 已识别插件自身消息（以 `【多多盯价】` 开头），避免平台回显导致自问自答。
